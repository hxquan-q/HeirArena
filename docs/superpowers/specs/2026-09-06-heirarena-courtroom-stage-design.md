# HeirArena 庭审舞台与 Agent 演出设计

## 目标

HeirArena 面向希望观看、介入多 Agent 遗产博弈的玩家。本轮只优化庭审体验，页面的单一任务是：**让玩家始终看清“谁在说、说了什么、现在能做什么”，同时把证据、关系和裁决保留为可随时调取的卷宗。**

不改变 SSE、庭审状态机、证据、显灵、入局、暂停、竞猜和裁决逻辑，不迁移到 Next.js。现有 React 19 + Vite 8 架构继续保留；参考 Pxlkit 的组件契约与 Next.js 展示项目的界面编排，而不是为了参考技术栈重写路由和构建系统。

## 方向选择

考虑过三种布局：

1. **舞台叙事优先（采用）**：主舞台占首屏约 70–80%，左右资料栏改为叠加抽屉。最适合娱乐化庭审和 Agent 演出。
2. 信息效率优先：保留三栏常驻。查询快，但当前截图已证明角色、台词和操作区被压缩。
3. 平衡模式：保留一栏、收起一栏。改善有限，仍会让窄屏舞台承担不稳定宽度。

用户已授权采用全部推荐项，因此选择方案 1。

## 设计系统

### 色彩

- **夜色胡桃** `#17120F`：页面与舞台外壳
- **法庭木饰** `#2E231C`：工具坞、抽屉和角色席
- **落槌黄铜** `#E2B25A`：当前阶段、主行动、聚光边缘
- **火漆异议** `#D9483B`：攻击、错误与高风险动作
- **结盟玉绿** `#3FB27F`：连接、完成与联盟
- **幽灵紫** `#A58BFF`：玩家显灵、军师与超自然事件

沿用现有 token，新增组件只引用语义类，不在 JSX 中扩散新色板。

### 字体

- **展示与状态**：Fusion Pixel 12px Proportional SC。用于阶段、角色名、计时和短标签。
- **正文与长台词**：系统中文无衬线。用于高密度阅读，避免像素字体承担长段落。
- **数据**：JetBrains Mono / Cascadia Code。用于时间、百分比、能量和回合数。

### 形态

保持 2px 像素边、硬投影和零/小圆角。舞台内允许少量圆形光晕表达“正在发言”，但外层面板不混用玻璃拟态与大圆角卡片。

### 动效

- 角色换位使用弹簧，保留空间连续性。
- 状态切换使用 160–280ms 的短过渡；思考、发言与情绪各有唯一动作。
- 落槌与阶段切换是两次编排好的高光，不给每张卡片添加无意义漂浮。
- 所有持续动效尊重 `prefers-reduced-motion`；降低动态时保留颜色、文本和图标状态。

## 页面结构

### 桌面端（≥1280px）

```text
┌ 返回 / 案名 ─────── 阶段轨道 ─────── 计时 / 休庭 / 连接 ┐
│ [卷宗]                                              [洞察] │
│ ┌──────────────────────────────────────────────────────┐ │
│ │                    法 庭 主 舞 台                     │ │
│ │       座席          聚光辩席           执行官          │ │
│ │                 当前角色 + 状态光环                    │ │
│ └──────────────────────────────────────────────────────┘ │
│ ┌ 当前发言：角色名 / 身份 ─────────────────────────────┐ │
│ │ 完整流式台词；元数据与论点标签位于次级行              │ │
│ └──────────────────────────────────────────────────────┘ │
│ [角色席横轨]                                             │
│ [显灵能量 / 技能 / 输入 / 发送]                          │
└──────────────────────────────────────────────────────────┘

左抽屉：时间线 + 证据卡牌
右抽屉：庭审记录 / 关系图 / 法定份额 / 裁决 / 入局简报
```

- 两个抽屉覆盖舞台边缘，不改变舞台尺寸，支持遮罩、Escape 关闭和焦点回收。
- 桌面默认全部关闭。出现新证据、裁决或轮到玩家时，只高亮入口，不自动遮挡发言。
- 顶栏只保留全局状态；低频模型信息进入“洞察”抽屉。

### 平板与手机

```text
┌ 案名 / 阶段 / 连接 ┐
│    自适应舞台       │
│ 当前发言完整卡片    │
│ 横向角色席          │
│ 玩家行动坞          │
└ 卷宗 ─────── 洞察 ─┘
```

- 抽屉变为底部 sheet，占高不超过 85dvh。
- 舞台保持固定宽高比，不产生横向页面滚动。
- 关键按钮触控区域至少 44×44px。

## 组件边界

### `CourtroomPage`

只负责实时数据组合、顶栏、舞台布局和抽屉开关。移除常驻三栏网格，不复制面板业务。

### `CourtDrawer`

通用的可访问抽屉外壳：

- `side: left | right`
- `open`, `onClose`, `title`, `children`
- 打开后把焦点移到标题/首个控制项，Escape 关闭，关闭后归还触发器焦点
- 桌面侧滑、移动端底部滑入

### `CourtroomHUD`

把“卷宗”“洞察”、阶段、计时、暂停和连接状态组成安静的 HUD。徽标只在状态变化时强调。

### `ActiveTestimony`

从当前或最近发言派生，展示：

- 角色头像、名字、身份和状态
- 完整流式台词
- 焦点议题、攻击/结盟等元数据
- 流式进行中指示和“查看庭审记录”

没有发言时给出当前阶段的明确引导，不显示空白卡。

### `AgentRoster`

横向角色席是舞台的状态图例，而不是第二份角色资料表：

- 头像、姓名、份额和当前状态
- 当前发言者置于视觉中心并提高一档对比
- 键盘可横向浏览；窄屏允许惯性滚动

### `AgentSprite`

保留程序化人物生成，重新收敛状态演出：

- `idle`：低频 2 帧呼吸
- `thinking`：头顶三点思考，身体不晃
- `speaking`：嘴型节奏 + 轻微前倾 + 地面声波环
- `angry`：一次短促后坐/震动，随后静止为怒眉
- `happy`：一次上扬与星光，不持续弹跳

不混用 SVG `animate`、CSS 无限动画和 Motion 来表达同一个状态。外层位移由 Motion 管，角色内部帧动画由 CSS/SVG 管。

### Pxlkit 与 3D

- 继续使用 `@pxlkit/ui-kit` 的 pixel surface、徽标、提示、分段控件与图标。
- Pxlkit 仓库与官网已展示 `@pxlkit/voxel`，但 npm 官方注册表当前仍返回 404；因此不新增不可复现依赖。现有 `gridToPixels + R3F Instances` 继续承担同等职责，并参考官方 `pxlToVoxels` 的数据边界保持转换与渲染解耦。
- 体素只用于落槌/闭庭等仪式性节点，不在普通面板里重复放置。

## 数据与状态

- 抽屉开关、本地标签选择是页面 UI 状态，不写入 `useCourt`。
- 发言内容继续以 `activeTurnId`、`turns` 和 `statuses` 为唯一来源。
- 当前发言为空时回退到最后一条 60 秒内发言；超过后进入阶段引导态。
- 新证据数量、入局等待和裁决状态只驱动入口徽标，不触发强制打开。
- 现有 `jumpToTurn`、证据选择、技能施放和 Seat 草稿流程保持原接口。

## 错误与空状态

- 连接中断：HUD 显示明确状态，舞台保留最后画面，抽屉仍可查看已收到记录。
- 尚未收到案件：舞台显示“卷宗送达中”，不渲染空侧栏。
- 无证据/无关系/无裁决：各自面板保留现有空状态，但补充下一步动作。
- 3D 加载失败不能阻断庭审；退化为 PxlKit 2D 图标。

## 验收

1. 1440×900 下舞台与发言区占主要首屏，左右资料默认不占布局宽度。
2. 玩家不用打开抽屉即可识别当前阶段、发言者、完整台词和可用行动。
3. 左右抽屉可由鼠标和键盘打开、Escape 关闭，并正确恢复焦点。
4. 375px、768px、1024px、1440px 无页面横向滚动；移动端操作区不遮挡台词。
5. Agent 五种状态无需只靠颜色即可区分。
6. 降低动态模式下不出现持续位移或闪烁，功能信息不丢失。
7. 庭审、证据、显灵、Seat、暂停、裁决流程与现有行为一致。
8. 前端 build、lint 与相关测试通过；浏览器检查桌面与移动视口。

## 非目标

- 不迁移 Next.js。
- 不重做后端、SSE 或庭审状态机。
- 不重新绘制完整角色资产，也不引入新的写实 3D 法庭。
- 不全站换肤；大厅和建案页仅共享必要的新基础组件。
