# HeirArena 开源文档重构设计

## 目标

把仓库统一定位为 **像素风 Web 剧本杀式多 Agent 案件利益沙盘**：玩家可以旁观导演，也可以选择案件当事人身份，围绕明确诉求参与推演；系统在《民法典》继承规则边界内完成遗产分配，并提供法律、策略、剧情三层结果。

## 一句话定位

HeirArena 是一个像素风多 Agent 案件利益沙盘：选择身份与诉求，在 AI 角色的结盟、举证、谈判和庭审博弈中推演遗产分配。

## 产品边界

- 当前已实现：建案、文本导入、模型分配、多 Agent 庭审、幽灵插话、暂停续庭、规则裁决、资产分配和庭审导出。
- 产品方向：在现有幽灵导演模式之外，增加“我是案件中的谁”的角色扮演模式，以及个人利益目标和策略复盘。
- 文档必须明确区分“当前可用”与“路线图”，不能把规划功能描述成已经上线。
- 项目用于娱乐化模拟、教育和策略推演，不构成法律意见，也不预测真实诉讼胜率。

## 玩家体验闭环

1. 建案：选择内置剧本，或导入 Markdown / 纯文本案情。
2. 入局：选择旁观导演或案件当事人；当事人获得身份、公开事实、私密诉求和利益目标。
3. 博弈：围绕争议焦点发言、结盟、举证、提案和让步。
4. 裁决：规则引擎计算法律基线，Agent 仅在可追溯事实和限定裁量范围内解释与调整。
5. 复盘：同时给出法律结果、个人利益达成度和剧情关系变化。

## 结果模型

| 层 | 输出 |
| --- | --- |
| 法律层 | 法定份额、成立事实、法条依据、资产归属、补偿关系 |
| 策略层 | 诉求完成度、收益变化、关键有效行动、失误与替代方案 |
| 剧情层 | 联盟与冲突、人物关系变化、戏剧值、像素结局称号 |

## 文档信息架构

- `README.md`：面向第一次访问仓库的人，先展示产品定位和实机画面，再提供玩法、当前能力、快速启动、架构摘要和路线图。
- `docs/product.md`：产品理念、玩家模式、核心循环、结果模型和功能边界。
- `docs/architecture.md`：前后端、Agent、规则引擎、持久化和 SSE 数据流。
- `docs/diagrams.md`：可编辑 Mermaid 图表，包括玩家流程、系统架构、庭审状态机、裁决双路径和目录结构。
- `docs/images/`：实机截图；至少覆盖大厅、案件设置或导入、庭审和裁决。
- 删除原有 `EstateGraph-Agent-*` 文档，避免律师 SaaS、OCR、RAG、图数据库等未实现路线干扰 HeirArena 定位；其中与现有规则引擎相关且准确的内容并入新文档。

## 图文规则

- 只使用本地运行项目的真实截图，不使用生成图冒充实机画面。
- README 首屏使用大厅或庭审横幅图，核心流程使用 2×2 图文布局或连续截图。
- Mermaid 源码直接保存在 Markdown，确保 GitHub 可渲染、可维护。
- 所有内部链接使用相对路径；删除不存在的 `docs/screenshot-courtroom.png` 引用。

## 架构原则

- LLM 负责角色表达和符号化事实；规则引擎负责确定性份额计算。
- 戏剧值、攻击和联盟影响过程与策略复盘，但不能直接篡改法定份额。
- 影响裁决的事实必须可追溯到案情输入或庭审回合。
- 模型不可用时逐句回退到剧本模式，保证游戏流程可运行。

## 验收标准

- README 不再以“你是立遗嘱的人”为唯一视角，清楚表达导演与角色扮演双模式。
- 不再出现把 HeirArena 描述为 EstateGraph 律师分析 SaaS 的主文档。
- README 与 docs 至少包含四张真实实机截图或明确说明因运行状态无法捕获的画面。
- `docs/diagrams.md` 至少包含五张与当前代码一致的 Mermaid 图。
- 文档中的路径、启动命令、API 和技术栈与仓库实际内容一致。
- 后端测试和前端构建通过。
- 功能分支已纳入 `main`；更新提交推送到远程，已合并分支安全删除。
