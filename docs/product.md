# HeirArena 产品说明

## 产品概念

HeirArena 是一个像素风 Web 剧本杀式多 Agent 案件利益沙盘，主题聚焦遗产继承争议。用户建立或导入案件后，由遗嘱执行官与多名案件角色围绕公开事实、资产诉求和继承规则完成陈述、辩论、协商与裁决。

它把三种体验放在同一个沙盘里：

- **规则推演**：用确定性法律引擎给出法定继承基线；
- **利益博弈**：让不同性格和诉求的 Agent 攻防、结盟、提案和让步；
- **故事演出**：以像素法庭、流式台词、人物反应、幽灵插话和戏剧值呈现过程。

当前产品的交互身份是**导演 / 幽灵**：用户设置案件和模型，旁观庭审，收集证据，押注结果，并消耗显灵能量施放不同干预。用户选择某位继承人亲自入局、获得私密目标并以个人利益最大化为目标的玩法仍属于路线图。

## 目标用户

- 希望体验 AI 群体博弈、互动叙事和像素风法庭演出的玩家；
- 用于课堂演示、工作坊或普法讨论的教师、学生和法律科技爱好者；
- 研究多 Agent 编排、模型路由、规则系统与生成式叙事结合方式的开发者；
- 希望对虚构或脱敏继承争议做情景推演的创作者与产品团队。

HeirArena 不是律师办案系统，也不以替代专业法律服务为目标。

## 五步玩家循环

这五步描述完整的产品体验；括号中明确当前状态。

1. **建案**（当前可用）  
   从内置剧本开始，或上传 / 粘贴 UTF-8 编码的 Markdown、纯文本案情；核对逝者、家庭成员、关系、法律事实标签、资产、估值与庭审参数。
2. **入局**（部分可用）  
   当前以导演 / 幽灵身份进入；选择某位继承人身份、接收私密诉求和个人利益目标属于路线图。
3. **博弈**（部分可用）  
   当前由角色 Agent 自动完成陈述、围绕争议焦点辩论并最终协商，用户可以旁观、休庭 / 续庭及幽灵插话。玩家以角色身份亲自发言、举证、结盟或让步属于路线图。
4. **裁决**（当前可用）  
   规则引擎先计算法定份额，执行官只可依据受约束、可追溯的当庭事实在设定幅度内调整，再把份额落实到具体资产和折价补偿。
5. **复盘**（部分可用）  
   当前可查看法定依据、庭审记录、成立事实、未决问题、分配与戏剧统计，并导出 Markdown。个人利益达成分、关键行动归因和策略重放属于路线图。

## 两种玩家模式

### 导演 / 幽灵模式（当前）

用户控制案件边界，而不是扮演某一名继承人：

- 选择预设或导入文本，编辑公开故事、成员、资产与法律事实；
- 为全局、执行官或单个角色分配模型，也可指定剧本模式；
- 设置辩论轮数、播放速度和裁决可偏离法定份额的最大幅度；
- 旁观多 Agent 庭审，以逝者的幽灵身份向下一位发言者插话；
- 查看案件时间线、证据卡牌、资产争夺热度、阵营网络和终局预测；
- 在裁决前押注谁会取得最高价值份额；
- 按阶段恢复显灵能量，施放质疑、出示证据、反驳、请求归纳和终极显灵；
- 在当前发言结束后的节点休庭，并从检查点续庭；
- 查看裁决、资产归属、补偿关系和庭审导出。

幽灵插话会影响后续角色表达和戏剧过程，但不会凭自身直接改写法定份额。

### 角色扮演模式（路线图）

目标体验是让玩家选择“我是案件中的谁”，并围绕该角色的利益亲自决策：

- 获得身份信息、公开事实、私密目标与偏好；
- 在回合中选择发言、举证、结盟、提案、交换或让步；
- 以法律边界内的个人收益和目标完成度衡量结果；
- 复盘有效行动、失误、可替代策略，并重放关键分支。

以上能力尚未作为当前功能交付。现有成员的 `wish`、Agent 自动生成的诉求以及攻击 / 结盟记录，不等同于玩家身份、私密目标、利益最大化评分或策略重放。

该模式已拆分为可独立实施的工程任务，详见 [`../task/README.md`](../task/README.md)；任务文档是路线图，不代表对应代码已经上线。

## 三层结果

| 结果层 | 产品目标 | 当前交付状态 |
| --- | --- | --- |
| **法律层** | 法定份额、继承顺序、适用条文、成立事实、受限调整、资产归属与折价补偿 | 已交付。确定性规则提供基线，裁决调整受事实类型和用户设置的幅度共同约束 |
| **策略层** | 诉求达成度、收益变化、关键有效行动、失误、替代方案与策略重放 | 已有证据卡、资产主张预测、争夺热度、阵营网络、庭前押注和论点评估；个人身份目标评分与策略重放未交付 |
| **故事层** | 角色关系变化、戏剧冲突、幽灵事件、庭审叙事和像素化结局 | 已交付过程演出、案件时间线、关系事件、角色反应、显灵技能、戏剧值与裁决叙事；分支结局称号可继续扩展 |

法律层约束最终分配，策略层解释“为什么这套行动有效或无效”，故事层负责可玩性和记忆点。戏剧效果与口才不能绕过法律层的约束。

## 法律边界

- 输出是娱乐化模拟、教育展示与情景推演结果，**不构成法律意见**，也不预测真实调解、仲裁或诉讼结果。
- 当前规则引擎覆盖的是代码中明示的有限法定继承规则，不是《民法典》、司法解释和裁判规则的完整实现；复杂遗嘱效力、债务清偿、证据采信、涉外继承、税务等事项不得据此直接下结论。
- 文本解析由模型提取事实，再经结构校验和部分原文引用核对；这不能证明材料真实、完整或具有法律效力。
- Agent 的指控、情绪、攻击和结盟默认只影响叙事。只有系统允许的自认、让步或多人确认等符号化事实才能进入当前裁决调整路径，且仍受幅度约束。
- 真实争议必须由具备资质的专业人士结合原始证据、有效法律和具体程序审核。

## 隐私与数据边界

- 继承案件通常含身份、亲属关系、财产和家庭冲突等敏感信息；演示时应优先使用虚构、匿名化或充分脱敏的数据。
- 文本导入、角色提示和部分庭审上下文会发送到所选模型供应商的 `base_url`。使用外部服务前，应核对其数据保留、训练、跨境传输和删除政策。
- 默认部署把案件、事件、发言、裁决和 LangGraph 检查点保存在后端数据目录；供应商配置保存在后端 JSON 文件。当前实现不提供字段级加密、租户隔离、用户认证、细粒度权限或审计后台。
- API Key 不会通过供应商列表接口原样返回前端，但文件型供应商配置会在后端本地文件中保存密钥；应限制数据目录和配置文件的操作系统权限，避免提交到版本库。
- Ollama、LM Studio 等本地 OpenAI 兼容端点可以降低内容发送到第三方的需求，但“本地端点”本身不自动等于安全部署，仍需评估主机、网络、日志和模型运行环境。
