# 「入局推演」任务总览

本目录把「入局推演」功能拆成 33 个可以逐个、独立执行的任务（T01–T33）。每个任务文件都自带目标、设计依据、代码锚点、实施步骤、验收标准与验证命令，可以在一个全新的会话里直接执行。

## 功能一句话

在现有庭审模拟之上加一个开庭模式：用户选定"我是案件中的谁"，用结构化 + 自由文本写下诉求；军师模型为**全员**生成私有策略简报和一张全员最优策略矩阵（对手也按自己的最优打，执行官对席位完全盲判）；用户可以让 AI 代理带简报上庭，也可以随时切换为亲自发言（有发言卡辅助，自认符号只能手动勾选）；裁决后按目标出确定性记分卡、叙事复盘与下一局建议。定位是**当事人沙盘 + 律师工具**：所有结论锚定规则引擎与当庭成立的事实，证据不足明说，像素外壳照旧。

## 命名约定

- 命名空间统一用 **`seat`（席位）**：`CaseInput.seat`、`backend/app/seat/`、`/api/seat/*`、`frontend/src/components/seat/`。不要用 `arena`——前端已有 `store/useArena.ts`（幽灵显灵能量存档），语义完全不同。
- 中文界面：卷名「入局」，模式名「入局推演」，开关叫「本席由我发言」，顾问模型叫「军师」。
- 静态的"杠杆 → 证据类型 → 法条"表叫**举证清单**（`legal/evidence.py`），不要叫"证据卡"——前端 `lib/evidence.ts` 的"证据卡牌 / 证据宝箱"是幽灵玩法里已有的东西。

## 执行方式

1. 开始一个任务前先读本 README，再读任务文件，再读任务里列出的锚点文件。锚点给的是函数名与大致行号，以当前代码为准。
2. 只做任务范围内的事。发现依赖任务没做完就先停下，不要顺手补。
3. 每个任务结束必须运行任务里的验证命令并确认通过；后端任务同时跑全量 `pytest`，前端任务同时跑 `npm run build`。
4. 任何任务都不得改变旁观模式（`case.seat is None`）的行为。现有测试不改一行就必须通过。
5. 提交粒度按任务，提交信息用 `seat(Txx): 一句话`。

## 设计决策全集

**定位与边界**
- 当事人沙盘 + 律师工具；严肃内核、像素外壳。策略建议必须标出依赖的事实与缺失的证据，证据不足标"无法认定，需补证"。
- 代理遵守律师伦理：只能强调可证明的事实、法律论证、锚定报价、以物换物、拉同盟、提示诉讼成本；禁止编造事实、引用不存在的法条、人身攻击、威胁。
- 开庭前事实固定。事实层靠 what-if 沙盘，庭上层靠资产归属、补偿与三种既有符号化事实（`admit_neglect` / `waive_share` / `acknowledge_support` ≥2 人）。
- 不在本期：庭上"证据卡"改变事实、虚张声势、对手强度开关、多次推演、Shapley 值、庭审中的实时 what-if。
- 入局模式关闭幽灵插话（`/interject` 返回 409，庭审页隐藏显灵行动栏）。

**诉求（每位成员一份）**
- 目标资产可排序（最多 5）、最低可接受**价值份额**（含折价补偿后的实际到手 / 净额；同时展示名义份额）、红线（模板：不接受出售[资产] / 不接受[成员]取得[资产] / 不接受低于法定 / 不接受与[成员]共有[资产]，另加自由文本）、软目标（枚举：与[成员]关系不破裂 / 宠物照护权 / 继续居住 / 付出被当庭承认，另加自由文本）、一段自由文本给代理演。
- 导入或选席时以 `wish` 预填；对手诉求由确定性规则推断，用户可编辑，可"恢复系统推断"。LLM 不修改任何人的诉求。
- 填诉求时实时算可达区间；最低份额超出上限给非阻断警告。
- 可入局成员：任何非宠物、非 AI 分身者（含保姆、前任等），矩阵诚实给出"无法定份额"及原因。

**军师与简报**
- 新增模型槽位「军师」，默认跟随执行官模型；负责矩阵策略要点、全员简报、发言卡、轻量 meta 抽取、软目标与自定义红线评分、叙事复盘。
- 简报七节，每条可勾选启用 / 删除 / 新增自定义：① 法定基线与法条；② 可达区间；③ 杠杆清单（依赖事实 · 当前状态 · 所需证据 · 预期份额变化 · 置信度或弃权）；④ 资产策略；⑤ 谈判剧本（开场要点、辩论回应对象、协商底线）；⑥ 对手预判与应对；⑦ 风险提示（哪些话一出口就构成 `admit_neglect` / `waive_share`）。
- 人设是策略的参考输入（孝顺型少攻击多结盟、贪婪型高锚定、律师型条文程序、佛系早让步换关系）；代理语气按人设、策略按简报；涉及会动份额的符号和资产诉求时简报优先。
- 信息隔离：成员 i 的简报只能看到 ① 公开信息（案情、全员 wish、人设、法定地位、确定性分析）② 成员 i 自己的诉求。玩家的简报额外可以看到全员诉求（包括用户编辑过的对手诉求）。对手简报**绝不**包含玩家的最低份额、红线、软目标、自由文本，也不包含其他对手被用户编辑过的诉求。
- 执行官（开庭词、焦点归纳、辩论引言、协商引言、裁决）所有提示词不含任何席位信息。
- 开庭前在第 IV 卷生成并展示，改诉求可反复重算；结果随开庭请求提交并落库。全员都带简报上场，每人私有。

**博弈层（全部确定性、不调模型）**
- MVP：a 联盟可行性（围绕"确认扶养须 ≥2 人"）、b 不可分资产竞争表（复用分配器的"能否吃下整件"与偏好分）、c 我的策略收益表（离散选项逐个喂分配器）。
- 紧随其后：d 对手最佳回应与稳定组合（离散选项穷举，标为"预计均衡结局"）。

**庭审交互**
- 席位开关「本席由我发言」随时可切；轮到我时读一次布尔值。开着就进入等待，关着 AI 代理说。
- 等待无超时；界面有「改由 AI 代说」；等待状态落库，刷新页面、重启服务后仍停在等我这一步；重启不自动续跑。
- 轮到我时自动生成 2~3 张发言卡（标注回应谁 / 是否建议某种自认 / 服务简报哪一条）；卡片**永不**自动勾选自认。
- 我的发言：正文 ≤ 500 字；动作 / 目标 / 资产诉求由军师轻量抽取并可改；自认只能显式勾选，勾选时实时提示后果（少分 3 个百分点等，与 `_fact_based_plan` 的步长一致）。
- 发言顺序不变，玩家无先后手优待；玩家发言同样计入 stats 与 drama。等待中 `/pause` 返回 409。

**结束与交付**
- 确定性记分卡给全员，叙事复盘 + 下一局建议只给玩家（1 次军师调用，软目标与自定义红线评分并入同一次调用）。
- 达成度公式公开：目标资产 40 分（第一目标占其中 60%、第二 30%、第三 10%）、最低份额 30 分（未达按缺口线性扣）、红线 20 分（破一条本项归零且总分上限压到 40）、软目标 10 分。未设定的项不计分，总分按已设定项换算到 100 并注明。
- 导出新增「入局推演报告」章节（全部内容）。
- 未接入模型时允许入局并降级：确定性部分照常；军师区块显示"需接入模型"；仍可打字发言（meta 全走表单）；界面标注"剧本对手不会执行策略"。

**入口**
- 设置页新增第 IV 卷「入局」：模式切换（旁观全员 / 入局推演）、选"我是谁"、诉求表单与可达区间、对手推断诉求（折叠可编辑）、what-if 沙盘、「推演策略」（矩阵 + 简报 + 博弈表，矩阵行可展开对手完整简报）、席位初值、「开庭」。默认旁观时只剩模式切换与开庭。
- 导入页解析结果加「我是 ___ → 以此视角入局」。军师槽位放在第 I 卷现有模型分配面板，旁观模式下提示"仅入局模式使用"。

## 全局不变量（各任务的测试共同守护）

1. 执行官的任何提示词不含诉求、简报、席位信息。
2. 份额只随三种符号化事实变动；玩家的自认只来自显式勾选。
3. 对手简报不含玩家的私有诉求，也不含其他对手被编辑过的诉求。
4. `case.seat is None` 时，后端事件序列、提示词、导出内容与改动前逐字节一致。
5. 等待玩家的会话重启后仍处于等待，不会被自动续跑。

## 技术约定

- 后端：Python 3.10+，FastAPI + pydantic v2 + LangGraph；测试 `cd backend && .venv/Scripts/python -m pytest -q`（Windows）。新模块放 `backend/app/seat/`，测试放 `backend/tests/test_seat_*.py`，沿用 `conftest.py` 的临时目录 fixture。
- 前端：Vite 8 + React 19 + TypeScript + Tailwind 4 + Zustand；`cd frontend && npm run build`（tsc + vite）与 `npm test`（vitest）。
- **UI 一律使用 PxlKit**（`@pxlkit/ui-kit` 组件、`@pxlkit/core` 的 `PxlKitIcon`、`@pxlkit/gamification|feedback|social|ui` 图标）。使用前先在 `frontend/node_modules/@pxlkit/ui-kit/dist/index.d.ts` 里查该组件的 props。可用组件包括：`PixelSegmented PixelSwitch PixelCheckbox PixelSelect PixelCombobox PixelNumberInput PixelInput PixelTextarea PixelChip PixelChipGroup PixelBadge PixelAlert PixelProgress PixelTypewriter PixelTooltip PixelAccordion PixelTabs PixelDataTable PixelDrawer PixelModal PixelCard PixelStatCard PixelEmptyState PixelSkeleton PixelButton PixelIconButton PixelBarChart PixelSparkline PixelTimeline`。像素风工具类沿用 `panel-elevated panel-inset pixel-text chip btn-gold btn-ghost input-base eyebrow`。不要引入其他 UI 库。
- 代码风格：中文注释只解释非显然的意图；不写复述代码的注释；pydantic 模型 `extra="forbid"`；TS 严格类型，不用 `any`。
- 所有 LLM 输出只能是结构化 JSON，经 pydantic 校验；影响份额的数值永远由规则引擎产生。

| 席位 / 玩家 | 用户选定的"我是谁"（`seat.player_id`） |
